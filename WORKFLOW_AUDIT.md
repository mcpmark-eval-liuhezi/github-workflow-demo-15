# Workflow Audit

This page documents how branches, pull requests, issues, and close-out fit together in this repository's tidy GitHub workflow.

## How It All Fits Together

1. **Branch** — Development work starts on a dedicated feature branch (e.g. `feature/audit-notes`) off the default branch (`main`).
2. **Pull Request** — A PR (`Add workflow audit notes`) proposes merging the branch into `main`, giving review, conversation, and CI a single place to happen.
3. **Issue** — Work items, checklist tasks, and follow-ups are tracked as issues (e.g. "Demo: workflow checklist"). Sub-issues break a checklist into smaller, trackable pieces.
4. **Close-out** — When a checklist is done, a comment marks it complete and the issue is closed as `completed`, leaving follow-up work as its own open sub-issue.
